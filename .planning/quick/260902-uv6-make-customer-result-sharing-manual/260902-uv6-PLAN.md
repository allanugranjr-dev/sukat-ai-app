# Quick Task: Make customer result sharing manual

## Goal

Ensure a processed customer result is only visible to a dressmaker after the customer explicitly clicks “Send to dressmaker for review”. Preserve the existing customer, dressmaker, admin, storage, and backend boundaries, and keep previously shared results backward compatible.

## Task 1: Add a pre-share scan state across the backend adapters

- **Files:** `src/lib/types.ts`, `server/index.mjs`, `xampp/api/index.php`, `supabase/functions/process-scan/index.ts`, `supabase/migrations/20260902010000_manual_scan_sharing.sql`
- **Action:** Add a `ready_to_share` lifecycle value for provider-completed results, keep `ready_for_review` as the explicit customer-to-dressmaker transition, prevent organization staff from reading pre-share scans, and update Node, XAMPP, and Supabase processing/status contracts plus the migration/RLS and customer-update guard.
- **Verify:** Search each adapter for status allowlists and terminal-state checks; run the frontend typecheck/build and the relevant automated tests; inspect that new provider results stop at `ready_to_share` and that only shared statuses are staff-visible.
- **Done when:** All supported backend modes accept and persist the new pre-share state, customer sharing remains an explicit `ready_to_share -> ready_for_review` update, and no adapter accidentally auto-shares the result.

## Task 2: Reflect the manual transition in the customer and dressmaker UX

- **Files:** `src/App.tsx`, `src/styles.css`
- **Action:** Route `ready_to_share` results into the customer results screen, keep “Send to dressmaker for review” enabled until clicked, show clear ready-to-share versus shared messaging, and leave the dressmaker Reviews queue unchanged for shared results.
- **Verify:** Run `npm run typecheck`, `npm test`, `npm run build`, and inspect the responsive results action area at the local app URL.
- **Done when:** A fresh processed result shows an enabled send button, the button performs the existing update action, and after the click the success state is disabled and the result appears in the dressmaker review scope.

## Must-haves

- Provider processing never changes a new result directly to `ready_for_review`.
- The customer explicitly initiates the share transition by clicking the existing button.
- Dressmakers cannot read a customer’s pre-share result in Node, XAMPP, or Supabase modes.
- Existing `ready_for_review` and `verified` results remain shared and usable.
- Existing routes, auth, private asset access, orders, and role boundaries remain intact.
