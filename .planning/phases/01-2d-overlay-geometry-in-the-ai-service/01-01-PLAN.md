<objective>
Wire the already-computed silhouette geometry end-to-end into the scan response as
per-measurement 2D overlay guide lines, derived on the CPU. The pipeline currently
throws these profiles away inside `_anny_targets`; this plan hands them back and adds
an `_overlay_geometry()` helper that emits normalized image-space endpoints keyed to
the submitted view.

Purpose: Deliver PIPE-01 (emit per-measurement normalized guide-line endpoints keyed
to source view + per-view pixel dims) and PIPE-02 (CPU-only, no new model), the data
foundation Phase 2/3 render on the customer's real photo.
Output: `_overlay_geometry()` + the `_anny_targets` 3-tuple refactor in pipeline.py,
attached as a dict on `ReconstructionMetadata` (extra="allow"); a new
`test_overlay_geometry.py`; and the arity fix to the two existing monkeypatched tests.
The declared Pydantic schema + clean-rejection validation is plan 01-02.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| crafted scan image -> silhouette extraction -> overlay derivation | Attacker-influenced image bytes drive segmentation; derived overlay coordinates then flow into the response. Untrusted input crosses here. |

Scope note: this plan adds NO new network endpoint, NO auth/session surface, and NO
PII — it derives geometry from images the pipeline already processed. Pydantic
schema validation + clean rejection is added in plan 01-02; this plan mitigates at
the derivation layer via clamping and omission.

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
